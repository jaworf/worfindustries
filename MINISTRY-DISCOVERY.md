# Ministry discovery
Church administrators open Settings → Member registration to copy their unique registration link. Links may be paused or replaced. Existing participants retain access to their own church profiles.
Leaders open My Ministry Profile with their existing account. Participation does not change staff permissions. Members need a verified email and acknowledge their church's sharing notice.
The workflow contains welcome paragraphs, a skills profile, a 30-question Ministry Motivations inventory, and an adapted 120-question Big Five inventory. Each assessment has independent completion, versioned results, retakes, private saved progress, and downloadable PDF reports. Reports use approved review-sheet content in app/discovery/content.json. The adapted inventories describe self-reported preferences; they do not provide population norms or clinical diagnoses.
Members intentionally share profile updates. Leaders see the submitted profile and assessment summaries, while individual answers and private drafts remain owner-only. Emotional-stability scores and facets are excluded from leader search and summaries. Observations are attributed and are not included in the general profile text search.
People Directory includes church-specific profile and assessment filters. Editors/admins must confirm the People connection: approve a suggested name/email match, search another record, or create a private People record. No automatic identity matching or cross-church linkage occurs.
Native app version 1.2 (15) includes profile search, summaries, matching, observations, and church-link sharing. Assessment completion opens the responsive web workflow using the same account; signing into the browser may be necessary. Native distribution requires a separate App Store/TestFlight release.

## Deployment
Apply supabase/migrations/20261027052447_ministry_discovery.sql before deploying the frontend. Supabase Auth must allow https://ministryvolunteers.worf.app/discover and https://ministryvolunteers.worf.app/discover/** as confirmation destinations. Preserve existing password recovery and church application callbacks.
The migration adds discovery tables/functions without replacing existing placement tables. Authenticated mutations use explicit ownership or church-role checks inside narrowly scoped functions. Anonymous callers can only resolve an active, unguessable church-registration token to church name/id/slug. Other discovery functions deny anonymous execution; public tables use RLS and do not grant direct authenticated writes.
The database advisor identifies these intentional security-definer APIs and the deny-by-default observations table. Every endpoint checks its required authority; the token resolver returns no people or results. Existing Auth OTP-expiry and leaked-password-protection notices predate this release.
